# 出題品質規範（Item-Writing Quality Rubric）

> 給 **作者、reviewer、以及派給 agent 的 prompt** 共用的一致標準。
> 新增或修改任何 exam 題庫題目（`src/domain/exam/items/*.ts`）前必讀。
> 此文件固化了 #64 / #87 / #89 / #109 / #120 / #130 / #136 累積的教訓。
>
> 相關：[#87](https://github.com/nurockplayer/Jabiko/issues/87)（多解 audit 傘 issue）、
> #67（EOL/LF）、#120（語順打散）、#139（自動 lint）、#140（LLM-judge 語意關卡）、
> `src/domain/contentGuard.test.ts`（機器關卡）、`scripts/import-exam-items.mjs`（匯入 pipeline）。

---

## 0. 一分鐘 checklist（每批 merge 前逐項打勾）

- [ ] **唯一正解**：其餘 3 個選項在該語境都不成立——而且我**主動試過**有沒有第二解。
- [ ] **干擾接續成立**：干擾項在那個空格文法/接續上是通的（不是靠接續錯被秒殺）。
- [ ] **無近義雙解**：沒有任何干擾是「近義詞在這句也自然成立」。← 最常見的失敗。
- [ ] **hintZh 不洩漏**：不含 `meaningZh` 任一 ≥2 字 token（**機器會擋**，見 §3）。
- [ ] **promptLabel 無級數**：不以 `N1`–`N5` 開頭（**機器會擋**）。
- [ ] **漢字読み**：promptText 用「」標被考詞、選項全假名且彼此相異、**非同詞合法異讀**。
- [ ] **解析完整**：逐項說明正解為何對、每個干擾為何錯。
- [ ] **自然＋分級**：語境自然、beginner-safe、符合該 JLPT 級。
- [ ] **原創**：非抄官方考古題/教材/題庫網站。
- [ ] **格式**：id 命名規則、檔案 LF、promptText 用 `___`、promptLabel 用既有正規標籤。

> ⚠ §1–§6 的語意品質（尤其唯一正解、近義雙解、自然度）**機器擋不住**，必須人工或 LLM-judge（#140）親審。§7 與部分 §3 是機器強制的，見最後一節。

---

## 1. 唯一正解（最重要、最常踩雷）

**規則**：正解之外的 3 個選項，在該題語境下都必須**明確不成立**。出完題後，逐一把每個干擾代回空格，問自己：「母語者會不會也接受這個？」只要有第二個說得通，這題就是壞的。

**雙解是本專案反覆消耗 review 的頭號缺陷。** 近義干擾尤其危險——它語法通、語意也沾邊。

實例（皆為真實修正）：

| 題 | 壞在哪 | 修法 |
|---|---|---|
| 飾る（#136）| 干擾 `並べた`：「壁に写真を並べる」（把照片排在牆上）也成立＝雙解 | 換成 `落とした`（明確錯）|
| かす（#87）| 「図書館で本を貸す」缺主語時，讀者借出也通 | 加主語＋動機，逼出單解 |
| 寒い（#87）| 「店が混んでいて寒い」對寒冷場所也成立 | 改成「問題が難しい」語境 |
| 届く（N3）| 多義（送達/搆到/達到）三解 | 重設 4 選項只留「物品送達」|

**正面範例（設計時就逼出單解）**：
- 留守（#136）：「母は買い物に出かけていて、今は ___ です」干擾 `欠席/留学/休憩` 在此語境**全不可能**＝零歧義。
- 過ごす（#136）：用「一週間**を**」當受詞，`暮らす`（自動詞、不接時間 を）文法上直接不成立。

**技巧**：與其找「差不多錯」的干擾，不如設計讓干擾**語法或搭配硬性不成立**的語境（加主語、加受詞助詞、加轉折），把雙解空間關死。

---

## 2. 干擾項設計

1. **接續/語法要成立**：干擾項在空格的接續上要通；不能只因「接續錯」被秒殺（那不是在考語意，是送分）。例外：文法題本身就是在考接續時，接續差異**即**考點。
2. **語意/搭配明確不對**：與正解同類（同詞性、同場景），但搭配明確不通。
3. **不可近義雙解**：見 §1。
4. **漢字読み 專用**：干擾用 **清濁／長音／促音／近形假名／音訓混淆** 製造；
   - **不可放同一個詞的另一個合法讀音**（那樣兩個都對）。
   - 不用無意義的隨機假名（太好排除＝送分）。
   - 例：被考詞「都合」（つごう），干擾可用 `つこう`（濁音）、`つうごう`（長音）等近似但錯誤的讀法。

---

## 3. 不洩漏（部分機器強制）

1. **hintZh 不含答案 gloss**（**機器強制**）：hintZh 在作答**前**顯示，不得洩漏 `meaningZh`。
   `contentGuard.test.ts` 的演算法：把 `meaningZh` 以 `、，；,;/（）()「」` 切分，去掉 `…`／省略號／空白，取**長度 ≥2** 的 token，hintZh **不得包含任一 token**（**連括號內的字也算**）。
   - 例：`meaningZh:"立刻、趕緊（去做）"` → token 含 `去做`，hintZh 就不能出現「去做」。
   - 寫 hint 的訣竅：描述**情境/場景**（誰、在哪、做什麼），不要描述「答案的意思」。
2. **promptLabel 不含級數**（**機器強制**）：不得以 `N1`–`N5` 開頭。級數靠內部 `level` 欄位過濾，不可外露。
3. **promptText 不洩漏**：題幹本身不能暗示答案類別。
4. **語順題要打散**（#120）：`語順組合` 題顯示的詞塊必須 render-shuffle，不能照正解順序排好。
5. **成對呼應文法**：像「〜ば〜のに」這種前後呼應，不可只挖一格卻把另一半留在題幹當提示。

---

## 4. 自然 ＋ 分級

- 語境**自然**：像真實生活會出現的句子，不是為了考點硬湊。
- **beginner-safe**：題幹用詞不應比被考點還難（別用更高級的詞當背景）。
- **符合該 JLPT 級**：被考詞、語境、文法都落在該級範圍。

---

## 5. 原創

- **不抄**官方考古題、教材、題庫網站的原句。
- 可以參考「考點」（某個文法/詞彙常考什麼），但句子必須改寫成原創。

---

## 6. 解析（explanation）

- **逐項說明**：正解為何成立 ＋ **每一個**干擾為何不選。
- 點出陷阱類型（同音、近義、近形、方向相反、自他動詞…）讓學習者學到辨別點。
- explanation 顯示在作答**後**，可以含答案 gloss（不受 §3 限制）。

---

## 7. 格式慣例（多數機器強制）

- **漢字読み**：promptText 用「」標出被考詞；`instructionZh`「選出底線詞語的正確讀音。」；此題型**不需** hintZh（機器：漢字読み 要有「」、其餘題型要有 hintZh）。
- **promptLabel 用既有正規標籤**：`文法形式選擇`／`詞彙填空`／`漢字読み`／`文章脈絡`／`類義替換`／`詞彙用法`／`語順組合`。
  ⚠ mock-exam 藍圖**以字面完全比對** promptLabel 過濾，自創標籤（如「言い換え類義」）會被漏掉——務必沿用同題型既有 item 的標籤與 instructionZh。
- **id 命名**：`n{級}-{型}-{羅馬字}`，例 `n3-vocab-rusu`、`n3-grammar-tsumori`、`n3-kanji-tsugou`、`n3-syn-toutou`、`n3-usage-todoku`。id **全庫唯一**（匯入時跨 `items/*.ts` 檢查）。
- **promptText 用 `___`**（3 個底線）標空格；工廠會 `replace("___", expectedAnswer)` 自動生成例句。
- **options 恰 4 個、彼此相異**，且 `expectedAnswer` 必須在其中。
- **LF 換行**（#67）：`items/*.ts` 在 repo 為 LF。優先用 `scripts/import-exam-items.mjs` 匯入（自動正規化 LF）；手寫 node patch 時 `readFileSync→replace(/\r\n/g,"\n")→writeFileSync` 後再 `git add`。

## 機器擋得住 vs 擋不住（務必分清）

**`contentGuard.test.ts`（`pnpm check:exam`）＋ `import-exam-items.mjs` 已自動強制**：
- options 彼此相異、`expectedAnswer` ∈ options（`check:exam` 驗 ≥2 個；**恰 4 個** 由匯入器 `import-exam-items.mjs` 把關——手寫只跑 `check:exam` 時 3 個選項會漏掉，故新題一律走匯入器）
- id 全庫唯一
- promptLabel 不以 `N1`–`N5` 開頭
- hintZh 不含 `meaningZh` 的 ≥2 字 token
- 漢字読み 有「」；非漢字読み 有 hintZh
- 必填欄位非空、level 合法、LF

**機器擋不住、只能人工／LLM-judge（#140）親審**：
- **唯一正解 / 近義雙解**（§1、§2.3）← 最重要
- 干擾接續是否成立（§2.1）
- 日文自然度、分級恰當（§4）
- 原創性（§5）
- 解析是否逐項到位（§6）

> 一句話：機器保證「格式對、沒洩漏」，但「這題只有一個答案、句子自然」要靠人。出題與 review 時，把心力集中在機器顧不到的 §1/§2/§4。

## 流程（出一批新題）

1. 產候選（原創、生活語境、單解、干擾近義/近形）。
2. **親審單解**：逐題把干擾代回，主動找第二解（§1）。
3. 寫成 batch JSON → `node scripts/import-exam-items.mjs <path> --dry-run` 驗證 → 正式匯入。
4. `pnpm check:exam`（機器關卡）→ 同步 `contentStats.ts` 題數 → `pnpm test` / `pnpm build` 全綠。
5. 開 PR → **雙重 review**（subagent + codex，專盯雙解）→ 修 → merge。
6. （規劃中）#140 LLM-judge 當 merge 前語意第二道關卡。
